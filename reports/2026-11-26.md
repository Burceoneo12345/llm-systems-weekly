## TRL 把 AsyncGRPO 的逐 token 打包改成数组运算

`2026-11-25` `TRL` `已合并` `强化学习` `训练`

TRL 把 AsyncGRPO 在 rank 0 上逐 token 规划、打包微批次的 Python 循环改为 NumPy 整段比较和数组索引。作者用数学、对话和智能体轨迹核对了新旧实现，打包结果逐位一致。

在 4 张 B300 上回放 Qwen3-1.7B 的数学 rollout 时，单轮规划与打包从 18 秒降至 1 秒，每秒训练 token 数提高 28%。这个基准测的是回放训练。要判断昇腾上是否有同样的瓶颈，可以先量出 rank 0 的打包耗时和其余 rank 的等待时间。

## 奖励模型改用 NF4 后，119 对回答的排序翻转

`2026-11-20` `arXiv` `预印本 v1` `4-bit RL` `强化学习` `低精度`

论文考察奖励评分阶段的权重量化。在 RewardBench 的 2,985 对回答上，Skywork-Reward-V2 Llama-3.2-1B 的线性层权重从 BF16 量化到 NF4 后，准确率从 88.41% 变为 88.38%。逐对检查时，60 对由正确变错误，59 对由错误变正确，合计 3.99% 的偏好判断发生变化。

评估量化奖励模型时，可以同时记录总准确率与逐对翻转率。这组实验回答的是评分一致性问题，策略更新后的 reward 仍待测量。

## ARC 用组内早期反馈缩短同步 rollout

`2026-11-22` `arXiv` `预印本 v1` `强化学习` `训练` `推理`

ARC 在 slime 中利用同一提示下已完成回答的反馈，提前补入新的候选组，并允许暂缓的生成任务恢复。作者用 8 张 H20 对 Qwen3.5-35B-A3B 做了 20 步长推理训练，与 slime 默认配置比较。

在相同的 320 个有效组目标下，rollout 总耗时减少 37.39%，每小时进入训练的有效组数从 5.24 提升至 7.86。六项数学评测的平均分从 89.02% 变为 88.74%。

## AMD 用 FP8 激活修复 MI450 A0 的 4-bit MoE 输出

`2026-11-26` `ROCm aiter` `已合并` `AMD` `推理` `低精度`

MI450 A0 的 gfx1250-strict 目标缺少原路径使用的 FP4 矩阵指令，分组 MoE 会输出 NaN。FlyDSL 在该目标上保留 MXFP4 权重，改用 FP8 激活执行 A8W4，并对预先打包的 FP4 激活显式报错。

作者用单张 MI450 A0、256 个专家、16,384 个 token 和 top-6 路由验证了算子正确性。整模推理时，激活位宽变化带来的带宽成本仍待测量。

## HiCal 在推理前校准 HiF4 的三级缩放参数

`2026-11-24` `arXiv` `预印本 v1` `低精度` `推理`

HiCal 离线校准每个 64 元素块的 E6M2 缩放因子如何舍入，并为块内的 8 元素组和 4 元素组各选一个扩展阈值。推理时固定舍入偏置和两个阈值，仍按每块的实际幅值量化权重和激活，每块只走一遍编码流程。

作者对比了原始 HiF4、校准后的 HiF4 和 FP16。六项任务的平均分在 Qwen3-8B 上从原始 HiF4 的 72.29% 升至 73.20%，在 Qwen3-30B-A3B 上从 79.01% 升至 80.26%。对应的 FP16 参考值为 74.60% 和 81.40%。昇腾上的量化算子耗时仍待实测。

## FlashInfer 让 4-bit MoE 的同一 token 在换批后保持逐位一致

`2026-11-26` `FlashInfer` `已合并` `低精度` `推理`

FlashInfer 给 `MoELayer` 增加可显式启用的 `BatchInvariantFp4Config`。专家权重和激活可同用 NVFP4 或同用 MXFP4。固定输入和路由后，同一个 token 单独运行、换到另一批或改变批内顺序，专家层输出都应逐位一致。本次合入覆盖本卡持有全部专家的配置。

作者在 Rubin NVL4 上用 Qwen3、Mixtral、DeepSeek-V3 等模型的专家层形状做了对照。对逐 token 缩放的 NVFP4，启用自动调优并从 logits 计算路由时，相对各形状最快的现有后端，短解码（最多 16 个 token）的速度为 0.73 倍，长预填充（至少 4,096 个 token）为 1.04 倍。两项均为 MoE 层微基准的几何平均。

[合并记录与分场景基准](https://github.com/flashinfer-ai/flashinfer/pull/9901) · [两种 FP4 配置的实现](https://github.com/flashinfer-ai/flashinfer/blob/9ab958880daf64cfd28cecae42f019277d46c255/flashinfer/fused_moe/batch_invariant/runner_fp4.py#L3-L19) · [换批与重排测试](https://github.com/flashinfer-ai/flashinfer/blob/9ab958880daf64cfd28cecae42f019277d46c255/tests/moe/test_unified_moe_batch_invariant_fp4.py#L1841-L1884)

## CTRL 让策略更新和 rollout 同时使用同一张 GPU

`2026-11-20` `arXiv` `预印本 v1` `强化学习` `训练` `推理`

CTRL 让每张 GPU 上的训练进程和常驻 vLLM 采样进程通过 CUDA MPS 共享计算资源。优化器状态留在主机内存，策略权重逐层传入 GPU。训练可以先消费已就绪的样本，到发布下一版策略时再等待，从而限制采样所用策略的版本滞后。

作者在 4 张 H100 上用 Qwen3-14B 非思考模式训练 150 步，每步 128 条轨迹。在相同的版本滞后上限下，按训练消费的提示词和回答 token 计，CTRL 全程吞吐是 verl 异步分时方案的 1.27 倍。在 536 道 OlympiadBench 数学题上，取两个随机种子各自末三次评测的均值，CTRL 和基线的准确率分别为 63.6% 和 63.3%。

## PipeAxes 分开调度预填充计算和流水线级间的 INT4 激活传输

`2026-11-26` `arXiv` `预印本 v1` `推理` `低精度`

PipeAxes 将一次预填充分成几层一组执行，解码请求可以在两组之间插入。跨级传输时，发送端合并隐藏状态和残差，每 64 个通道做 Hadamard 旋转，把激活打包成 INT4 并附上 FP16 缩放因子。接收端恢复为 BF16，模型权重也保持 BF16。每次发送的激活行数可以独立于 GPU 批大小调整。

作者在两张 RTX 4090 和两张 RTX 3090 组成的四级流水线上回放 Qwen3-30B-A3B 的 32K 工作负载，跨机带宽设为 250 Mbps。21 个请求中，PipeAxes 有 16 个同时达到三项延迟目标，固定 4,096-token 分块加优先传输的方案有 4 个，Revisit-PP 有 1 个。这组结果包含调度与传输的共同作用。
